# Changelog

All notable changes to `@haoking/opencvjs`. The project follows
[semantic versioning](https://semver.org/).

## 4.0.0 — Unreleased

The toolchain moves from Emscripten 3.1.64 to 6.0.12 and the supported Node.js versions to
22 and later. 4.0.0 also contains everything prepared for 3.1.0, which was never
published: the fixes from a full-repository review. OpenCV stays at 5.0.0, and the
extension methods keep their names and signatures.

### Breaking changes

- **Node.js 22 or later.** `engines` was `>=18`; Node 18 and 20 reached end of life on
  2025-04-30 and 2026-04-30. CI runs 22, 24 and 26.
- **Newer browsers.** Code generated by Emscripten 6.0.12 needs Chrome 85+, Firefox 79+
  and Safari 15+, for both builds. The SIMD build still needs WebAssembly SIMD as well.
- **Native failures throw a `RuntimeError`.** A failed assertion inside OpenCV (native
  `roi()` out of range, for instance) used to throw a bare number (a heap pointer). It now
  throws `RuntimeError: Aborted(undefined). Build with -sASSERTIONS for more info.` and
  prints `Aborted(undefined)` to stderr. Neither carries any detail. Code that recognized
  aborts with `typeof e === "number"` must change. The extension methods are unaffected:
  they validate their arguments before calling into wasm.
- **23 Emscripten runtime internals are no longer on `cv`**: `calledRun`, `stdin`,
  `stdout`, `stderr`, `onRuntimeInitialized`, the browser main-loop helpers
  (`createContext`, `getUserMedia`, `pauseMainLoop`, `resumeMainLoop`,
  `requestAnimationFrame`, `requestFullscreen`, `setCanvasSize`) and 11 `dynCall_*` stubs,
  which BigInt integration made unnecessary. The ones with real uses are exported
  explicitly (see New). `cv.onRuntimeInitialized` lingering after initialization was a
  trap anyway: readiness is `typeof cv.Mat === "function"`.
- **Error messages are in English**, and some were reworded. Error types are unchanged,
  except that `reshapeRows(1.5)` throws `TypeError` (was `RangeError`), like the other
  methods, and `cv.matFromArray` rejects bad input with `TypeError` / `RangeError` before
  allocating (see Fixes).
- **The single-file build embeds the wasm as UTF-8** (Emscripten's default since 4.0.18;
  about 17% smaller than base64), so pages must decode the script as UTF-8. It is not
  part of the npm package.

### New

- **MCC color checker detection**: `cv.mcc_CCheckerDetector`, `cv.mcc_CChecker`,
  `cv.mcc_DetectorParametersMCC` and the `cv.mcc_ColorChart` enum. Upstream's whitelist
  misspells the class names, so 3.0.0 bound only the enum. Two patches make the bindings
  compile and initialize the detector's chart type, which upstream leaves uninitialized.
  See the README for usage and limits.
- **`using` and iteration.** Every Embind object has `[Symbol.dispose]` (its `delete()`),
  so `using m = …` frees a Mat at the end of the block, and Embind vectors
  (`cv.MatVector` and friends) are iterable. `index.d.ts` declares `[Symbol.dispose]` on
  `Mat`, plus a global `SymbolConstructor.dispose` for projects without
  `esnext.disposable`.
- **The heap grows up to 2 GB** instead of 1 GB. (Not 4 GB: above 2 GB Emscripten treats
  every pointer as unsigned in JS, which made Embind-heavy calls such as `roiClone()`
  about 40% slower.)
- **Runtime helpers exported explicitly**: the `HEAP*` views, `BindingError` /
  `InternalError` / `UnboundTypeError`, `flushPendingDeletes` / `setDelayFunction`
  (without them `deleteLater()` never frees anything), `count_emval_handles`,
  `getInheritedInstanceCount` / `getLiveInheritedInstances` and `FS_createPreloadedFile`.
  `FS_preloadFile`, its promise-based successor, is new.

### Fixes

None of these removes an API; each "before" contradicted the documentation or OpenCV's
semantics.

| Call                                                                        | Before                                                                                                        | Now                                             |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `PTR(row)` on a native `roi()` view                                         | returned the parent's whole row stride, past the buffer on the last row                                       | the row's cols × channels elements only         |
| `replaceMatOnRow` on a view                                                 | wrote past the view; on the last row into the next Mat                                                        | writes the row only                             |
| `sum()` / `reshapeRows()` on a view                                         | read contiguous memory: wrong result                                                                          | correct                                         |
| `addConstant` and co. on data with `±Infinity`                              | those elements became `NaN`                                                                                   | IEEE-754 arithmetic                             |
| `norm2` on integers (INF / L1 / L2 / L2SQR)                                 | saturated difference: `[0]` vs `[10]` on 8U gave 0                                                            | norm of the true difference, symmetric          |
| `norm2` with `NORM_RELATIVE`                                                | flag silently dropped                                                                                         | ‖src1 − src2‖ / ‖src2‖, as in C++               |
| `norm2` with `NORM_HAMMING` / `NORM_HAMMING2`                               | counted the bits of the (saturated) difference                                                                | bits of `src1 XOR src2`; `CV_8UC1` only         |
| `norm2` with an invalid `normType`                                          | abort                                                                                                         | `RangeError`                                    |
| `constantDivide(c)` on integers with `c` outside the depth or fractional    | `c` was saturated / rounded first: 1000 / 10 on 8U gave 26                                                    | `saturate(c / x)`: 100                          |
| `constantDivide` on a Mat with more than 4 channels                         | abort                                                                                                         | `TypeError`                                     |
| `constantDivide` on an N-dimensional Mat (a 3-channel `calcHist` result)    | `RuntimeError: memory access out of bounds`                                                                   | same result as on 2-D data                      |
| in-place writes into integer Mats (`rectAdd`, `addOnCol`, …)                | wrapped modulo 2^n and truncated: 250 + 20 on 8U gave 14                                                      | `saturate_cast`: 255, halves to even, `NaN` → 0 |
| `replaceMatOnRect` / `rectAdd` / `rectSubtract` with `src` overlapping      | read values just written                                                                                      | copy semantics                                  |
| a `rect` that is an object with getters                                     | validated and used from separate reads, so it could write past the target                                     | each field read once                            |
| `replaceMatOnRow` / `replaceMatOnCol` with an element `+x` cannot convert   | threw halfway, leaving part of the row written                                                                | `TypeError` before anything is written          |
| `reshapeRows()` when allocating the result grows wasm memory                | `TypeError` (detached ArrayBuffer), and the new Mat leaked                                                    | correct                                         |
| `cv.matFromArray` with an unknown type (a misspelt constant is `undefined`) | the glue allocated, then threw `Error("Type is unsupported")`, leaking the Mat                                | `TypeError`, nothing allocated                  |
| `cv.matFromArray` with fractional or negative `rows` / `cols`               | fractional: truncated by Embind, then `RangeError: offset is out of bounds`, leaking the Mat; negative: abort | `TypeError` / `RangeError` naming the argument  |
| asking for the other build in a process that already loaded one             | `BindingError`, after silently replacing the loaded instance's `matFromArray` check                           | `Error` before anything is loaded               |
| `replaceMatOnPoint(NaN, …)`                                                 | `TypeError` (treated as an operand)                                                                           | accepted: it is data                            |
| `dftSplit()` throwing (on an empty Mat, for instance)                       | its two output Mats leaked                                                                                    | released                                        |
| simd build: float → integer rounding                                        | upstream `v_round` is `trunc(x + 0.5)`: negatives 1 too high, halves rounded up                               | identical to `cvRound` and to baseline          |

The rounding fix is `build/patches/opencv-wasm-v_round.patch`: in a scan of 15 operations
over the 5 integer depths, the patched simd build matches baseline in every element
(unpatched: 43,078 of 270,791 elements differed). Baseline is unaffected; it is built
without intrinsics.

### Performance

Emscripten 6.0.12 against 3.1.64, same OpenCV and the same `test/simd-compare.js` cases
(arm64, node v22.22.2; each build in its own process, the minimum of two passes with
alternating order; above 1 means 4.0.0 is faster):

| Operation                       | baseline   | simd       |
| ------------------------------- | ---------- | ---------- |
| `warpAffine` 8UC1 256²          | **1.72x**  | 1.02x      |
| `Sobel` 32FC1 256²              | **1.14x**  | **1.12x**  |
| `roiClone` 32² of 64²           | **1.11x**  | **1.10x**  |
| `replaceMatOnRect` 32² into 64² | 0.97x      | 1.05x      |
| `dft` 32FC1 256²                | **0.94x**  | 0.98x      |
| `pyrDown` 32FC4 256²            | 1.02x      | **0.94x**  |
| the other six                   | 0.99–1.02x | 0.97–1.02x |

The gains and the two small slowdowns (baseline `dft`, simd `pyrDown`) reproduced in three
separate rounds of measurement. Loading (`require` until ready) takes about 34 ms with
either toolchain; resident memory right after loading is about 11 MB higher (99 MB
against 88 MB for baseline).

The in-place writes address the wasm heap directly instead of calling an Embind accessor
per pixel, as 3.0.0 did. In the `inplace-ops` gate (a 256×256 rectangle written into a
512×512 `CV_32FC1`) they run at the speed of a hand-written heap loop, while 3.0.0's
per-pixel native `floatPtr` calls are 143–197 times slower and per-pixel `PTR()` calls
288–373 times slower; for a 512-row column the factors are 19–26 and 40–50.

Evaluated and not adopted (geometric mean over the same cases, against the shipped build):
`-flto` +0.7% baseline / +1.3% simd for 28% / 24% more wasm; `-fwasm-exceptions` +0.3%
for 10% more wasm, a higher engine floor and native failures turning into
`WebAssembly.Exception` objects (their text readable through `getExceptionMessage`);
`-mrelaxed-simd` −0.2%. Each is described in `build/build.sh`.

### Build, CI and tests

- **Pinned inputs.** `build/Dockerfile` pins `emscripten/emsdk:6.0.12` by image digest,
  and `build/build.sh` checks that the OpenCV tag resolves to the commit in
  `build/opencv-commit.txt`.
- **Patches** (`build/patches/`): `opencv-js-deep-clone.patch` (with Emscripten ≥ 4.0.0
  upstream's deep-copy override of `clone()` never runs, so without it `clone()` is
  shallow and about half the test suite fails), `opencv-js-link-flags.patch` (the exports
  and the 2 GB limit above, set on the `opencv_js` target because CMake's `try_compile`
  probes reject unknown exports), `opencv-js-mcc-bindings.patch`,
  `opencv-mcc-chart-type-init.patch` and `opencv-wasm-v_round.patch`.
- **Fingerprinted artifacts.** `build/fingerprint.sh` hashes every build input;
  `build-wasm.yml` names its artifacts `opencv-wasm-<variant>-<fingerprint>`, and
  `ci.yml` downloads the artifacts matching the commit under test (it used to take the
  latest successful `build-wasm.yml` run of any branch, whatever it was built from) and
  fails with instructions when there are none.
- **CI**: Node 22 / 24 / 26; `actions/download-artifact` v8; build jobs time out after 45
  minutes and test jobs after 30; the parity test's child processes have time limits.
- **Tests: 205 → 251.** Regression tests for every fix above; MCC detection
  on a synthetic chart; two parity cases for float → integer rounding (16 in total);
  smoke-test checks for every export, deep `clone()`, `Symbol.dispose`, vector iteration
  and a 1.25 GB allocation; the artifact's OpenCV version against
  `build/opencv-version.txt`.
- `test/helpers.js` and `prepack` refuse a `dist/` that is out of sync with `src/js/`, so
  tests can no longer pass on stale code and `npm publish` cannot ship it.
- `build/assemble.sh` reads `OPENCV_ARTIFACT_BASELINE`; it used to reuse the smoke test's
  `OPENCV_ARTIFACT`, which put the simd wasm into `dist/baseline/` after smoke-testing simd.
- Comments, messages and documentation are in English.

## 3.0.0 — 2026-07-28

**The baseline moved from OpenCV 4.14.0 to 5.0.0** (released upstream on 2026-06-06). A
genuinely breaking upgrade: OpenCV 5 deleted a set of classes from its **C++ API**, and
code using them throws `TypeError`.

### Breaking changes

| Symbol                                              | Replacement                                                       |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| `CascadeClassifier`                                 | `FaceDetectorYN` (DNN, needs an ONNX model; unverified here)      |
| `HOGDescriptor`                                     | none                                                              |
| `AKAZE` / `BRISK` / `KAZE` / `AgastFeatureDetector` | `ORB` / `MSER` / `FastFeatureDetector` / `GFTTDetector` and so on |
| `groupRectangles`                                   | none                                                              |

This is not a whitelist choice: 5.0.0's `objdetect.hpp` and `features.hpp` no longer
declare these classes, and the Haar cascade data files are gone from the source tree. Their
enum constants (`CASCADE_*`, `AKAZE_*`, …) went with them.

Why major when 2.1.0 was minor: 2.1.0 only turned silent failures into exceptions, so no
correct code depended on what changed. Here `new cv.CascadeClassifier()` was documented,
working usage, and it breaks.

### Changes

- The whitelist is upstream 5.0.0's `platforms/js/opencv_js.config.py`, copied verbatim
  with three changes: the header comment, `dnn` removed from `makeWhiteList`, and
  `mulSpectrums` / `SVDecomp` added to `core` (their 5.0.0 declarations are identical to
  4.14.0's).
- Upstream's own changes: `features2d → features`, `calib3d → _3d + calib`,
  `divSpectrums` moved from `imgproc` to `core`, and new `mcc_*` entries — which bind
  nothing because they do not match the 5.0.0 class names (fixed in 4.0.0). `photo` is
  still there.
- `build/opencv-version.txt` → `5.0.0`; `build_js.py`'s options did not change.

### Measured on the published build

- Size (gzip `-9`, brotli quality 11):

  | ------------------------- | ------------ | ------------ | ------ |
  | `baseline/opencv_js.wasm` | 8,515,975 B  | 12,104,983 B | +42.1% |
  | gzip                      | 2,729,282 B  | 3,517,017 B  | +28.9% |
  | brotli                    | 1,992,519 B  | 2,565,667 B  | +28.8% |
  | `simd/opencv_js.wasm`     | 10,363,503 B | 14,595,094 B | +40.8% |
  | gzip                      | 3,109,590 B  | 4,030,751 B  | +29.6% |

- `Object.keys(cv)`: 1653 symbols (1450 on 4.14.0); still 75 Mat members.
- SIMD on arm64: `dft` 0.90x, `cvtColor` 0.99x; see the README for the full table.
- Found later: the simd build's float → integer rounding was off (upstream `v_round`,
  present in the 4.14.0 builds as well); fixed in 4.0.0.

## 2.1.0 — 2026-07-28

**Runtime SIMD detection with two wasm builds**, plus the argument validation and
TypeScript declarations accumulated since 2.0.0. `require("@haoking/opencvjs")()` is
unchanged.

### New

- **Runtime SIMD detection.** `loadOpenCV()` validates a 31-byte module returning `v128`
  (ending in `i8x16.popcnt`, from the final SIMD proposal) with `WebAssembly.validate()`,
  which is synchronous so the build can be chosen before `require`, and loads
  `dist/simd/` or `dist/baseline/`. Override with `loadOpenCV({ simd })` or `OPENCV_SIMD`
  (in that order of precedence). A build requested explicitly that is missing throws
  instead of falling back, and a misspelt `OPENCV_SIMD` throws too.
- **Three build variants**: `build/build.sh` (baseline), `--simd` and `--single-file`.
  Only baseline and simd go into the npm package; the single-file variant (baseline,
  without SIMD, since a `<script>` include has no fallback) is a CI artifact.
- **Variant parity test**: the same deterministic input through both builds on 14
  operations, bit-exact for integer kernels and the extension layer, and for float
  kernels `max|a − b| ≤ 1e-5 × max(‖baseline‖∞, 1)` — OpenCV's own criterion
  (`CV_PyramidBaseTest`'s 1e-5, `cmpEps()` without element-wise relative error). The
  first real SIMD build failed an element-wise relative criterion on pyrDown, where
  near-total cancellation inflated 1.6 ulp into "752 ulp"; the SIMD results were in fact
  closer to a double-precision reference than baseline's.
- **Argument validation** (`src/js/guards.js`) on every extension method and on `PTR()`:
  out-of-range rects and indices, size and type mismatches, short arrays, non-number or
  `NaN` constants (`±Infinity` is accepted), non-Mat and deleted-Mat arguments, and
  `cv.matFromArray` element counts, all raising `TypeError` / `RangeError` with the
  function, the argument and the value.
- **TypeScript declarations** (`dist/index.d.ts`) dumped from the build by
  `build/gen-types.js`, with a test asserting that the declared and runtime symbol sets
  are equal in both directions.

### Changed

- **`dist/` layout**: `dist/opencv.js` and `dist/opencv_js.wasm` moved into
  `dist/baseline/` and `dist/simd/`, because both builds' wasm files are named
  `opencv_js.wasm` at compile time. Only deep imports of
  `@haoking/opencvjs/dist/opencv.js` break; `main`, `types` and the entry point are
  unchanged. (The two glue files turned out to be byte-identical; the directories exist
  for the wasm files only.)
- **One build per process**: OpenCV's UMD wrapper leaks `Module` as an implicit global, so
  a second build collides with the first (`Cannot register public name 'IntVector'
twice`).
- **Package size** 8.3 MB → 19.4 MB unpacked (6.0 MB tarball): the second wasm. The SIMD
  wasm is 21.7% larger than baseline because OpenCV keeps its scalar paths next to the
  vector ones.

### Calls that now throw

These used to abort or silently produce wrong data:

| Call                                         | Before                                    | Now          |
| -------------------------------------------- | ----------------------------------------- | ------------ |
| `mat.addConstant(undefined)` / `NaN` / `"2"` | a Mat full of `NaN` / silently truncated  | `TypeError`  |
| `mat.addConstant(Infinity)` and co.          | worked                                    | still works  |
| `mat.colClone(1.5)`                          | silently took column 1                    | `TypeError`  |
| `mat.replaceMatOnRow([1], 0)` (short array)  | missing elements written as `NaN` / 0     | `RangeError` |
| `mat.addOnCol(1, 7)` (column out of range)   | silently overwrote heap memory            | `RangeError` |
| `cv.matFromArray(3, 3, CV_32FC1, [1, 2, 3])` | the rest was uninitialized heap memory    | `RangeError` |
| `mat.dftSplit()` on a multi-channel Mat      | read channel 0 only, returned garbage     | `TypeError`  |
| `mat.dftSplit()` on an empty Mat             | silently wrote out of bounds              | `RangeError` |
| `mat.PTR(9, 9)` on a 3×3 Mat                 | silently read / wrote foreign heap memory | `RangeError` |
| `mat.PTR(1.5, 0)`                            | silently truncated to row 1               | `TypeError`  |
| `mat.PTR(0, -1)`                             | taken as a "whole row" sentinel           | `RangeError` |

### Performance

SIMD speedups (arm64 / x86-64): `absdiff` 12.81x / 13.13x, `add` 10.37x / 11.23x,
`resize` 4.37x / 4.36x, `GaussianBlur` 3.32x / 2.60x, `pyrDown` 3.27x / 3.41x; `dft` is
0.91x on both, a real regression; `cvtColor` was 0.84x on x86-64 (not reproduced on 5.0.0).
Upstream's 2020 counterexample, `blur` CV_32FC1 at 0.519x, did not reproduce (1.55x /
1.44x). `npm run simd:compare` prints these numbers and only fails when it cannot run.

### Tests

189 → 205. CI runs the suite twice, forcing each build, with the parity and smoke tests
required (`OPENCV_PARITY_REQUIRED=1`, `OPENCV_SMOKE_REQUIRED=1`).

## 2.0.0 — 2026-07-28

**New artifact and a rewritten extension layer.** The 2018 asm.js file (13.9 MB, OpenCV
4.0.1) was replaced by a WebAssembly build of OpenCV 4.14.0 made by this repository, and
the extension layer moved into modules under `src/js/`, assembled into `dist/`. Migration
guide: [docs/MIGRATION-2.0.md](docs/MIGRATION-2.0.md).

### Breaking changes

1. **The entry returns a Promise**: `const cv = await require("@haoking/opencvjs")()`.
   Readiness is `typeof cv.Mat === "function"`.
2. **The artifact is two files**, glue plus `.wasm`, side by side under fixed names. The
   extension layer is CommonJS; browsers need a bundler.
3. **`main` is `dist/index.js`**, assembled by `build/assemble.sh` and not in git.
4. **Native methods are no longer overridden**; the fixed versions were renamed:
   `roi` → `roiClone`, `col` → `colClone`, `Diag` → `diagClone`, `reshape` →
   `reshapeRows`, and the escape names `_roi` / `_col` are gone.
5. **8 hand-written methods were removed** in favour of native equivalents: `mmul` →
   `cv.gemm`, `vconcat` / `hconcat` → `cv.vconcat` / `cv.hconcat` (with a MatVector),
   `mds` → `cv.meanStdDev`, `svd` → `cv.SVDecomp`, `RodriguesFromMat` /
   `cv.RodriguesFromArray` → `cv.Rodrigues`, `cv.mulSpectrums2Channel` →
   `cv.mulSpectrums`. `cv.mulSpectrums` keeps its name with the native signature
   `(a, b, dst, flags, conjB)`.
6. **The inlined numeric.js library is gone**; `Mat#sum()` became a plain JS sum with the
   same result.
7. **`Mat#dftSplit()` is deprecated** (nothing supports its correctness).
8. **OpenCV 4.0.1 → 4.14.0**, seven years of upstream changes; the dnn JS bindings were
   removed from the whitelist.

### Fixes

- `mds()` always threw (`this.DATA` instead of `this.DATA()`).
- `mulSpectrums()` / `mulSpectrums2Channel()` returned `NaN` and uninitialized memory.
- `replaceMatOnRow()` silently overran memory on anything but `CV_32F` (Embind's
  `floatPtr` does no type check); now correct on all seven depths.
- `constantDivide()` divided channels 1+ by zero on multi-channel Mats.
- `replaceMatOnPoint()`'s parameter names contradicted its behaviour, and the documented
  `(value, point)` overload did not exist; three-argument calls behave as before.
- `DATA()` / `PTR()` returned `undefined` for Mats with more than 4 channels.

### Tests and performance

114 → 135 tests. On 64×64 `CV_32FC1` with `Rect(1, 1, 32, 32)`, 20000 calls: native
`roi()` + `clone()` 14.0 ms vs `roiClone()` 14.3 ms — no overhead from the extension
layer.

## 1.0.0 — 2026-07-27

**The first npm release.** Changes relative to the repository's earlier state (`82b3fcc`,
which called itself 4.0.1):

- `roi()` / `col()` / `Diag()` crashed on `CV_8S` / `CV_16S` / `CV_32S` / `CV_64F` (the
  old implementation round-tripped through `cvtColor`) and silently returned wrong data on
  multi-channel Mats (a non-continuous view read as contiguous memory). They now return
  `clone()` copies: 5.8–8.6× faster on single-channel data, and no longer leaking an
  intermediate Mat per call (the old code exhausted the heap at call 43105). On
  multi-channel Mats this changed the result from a view to a copy, which 2.0 superseded
  by restoring the native methods and adding `*Clone`.
- A dependency-free test suite (`node:test`, 113 cases), a performance gate
  (`npm run bench`) and a Docker-based WebAssembly build pipeline, not yet used for this
  release, which still shipped the asm.js file.
